# IEEE-CIS Fraud Detection

## Kaggle-ის კონკურსის მოკლე მიმოხილვა
ეს პროექტი გაკეთებულია Kaggle-ის კონკურსისთვის **IEEE-CIS Fraud Detection**. ამ ამოცანის მიზანია საბანკო ტრანზაქციის სხვადასხვა მახასიათებლის მიხედვით ვიწინასწარმეტყველოთ, არის თუ არა ტრანზაქცია თაღლითური (`isFraud`). მონაცემები მოდის ორი წყაროდან: `train_transaction.csv` და `train_identity.csv`, რომლებიც `TransactionID`-ზე გაერთიანდა. Dataset შეიცავს 590,540 ტრანზაქციას, მათ შორის მხოლოდ ~3.5% თაღლითურია, რაც ძლიერ დაუბალანსებელ კლასებს ქმნის. შეფასების მეტრიკა Kaggle-ზე არის **ROC-AUC**.

## ჩვენი მიდგომა პრობლემის გადასაჭრელად
პრობლემის გადაწყვეტისას ჯერ მონაცემების გაწმენდაზე გავაკეთეთ აქცენტი — ბევრი ველი შეიცავდა 50%-ზე მეტ გამოტოვებულ მნიშვნელობას. შემდეგ გავაკეთეთ feature engineering: დავამატეთ დროის მახასიათებლები, ლოგ-ტრანსფორმაცია და სიხშირული კოდირება მაღალი კარდინალობის კატეგორიული ცვლადებისთვის. Feature selection-ისთვის გამოვიყენეთ **Information Value (IV)** მეტრიკა. გავტესტეთ 5 სხვადასხვა მოდელი, თითოეულისთვის ვცადეთ რამდენიმე ჰიპერ-პარამეტრების კომბინაცია, ყველა ექსპერიმენტი დავალოგეთ MLflow-ში DagsHub-ის საშუალებით. საბოლოოდ საუკეთესო შედეგი მიიღო **XGBoost**-მა, ამიტომ Kaggle-ისთვის საბოლოო `submission.csv` სწორედ ამ მოდელით შეიქმნა.

## Feature Engineering

### კატეგორიული ცვლადების რიცხვითში გადაყვანა
მაღალი კარდინალობის კატეგორიული ცვლადები (`card1`, `card2`, `card3`, `card5`, `P_emaildomain`, `R_emaildomain`, `DeviceInfo`, `id_31`, `id_33`, `id_20`) one-hot encoding-ის ნაცვლად **სიხშირული კოდირებით (frequency encoding)** გადავიყვანეთ რიცხვებში — თითოეული კატეგორიის ნაცვლად ჩაიწერა მისი შეხვედრის სიხშირე სატრენინგო სეტში. ეს აირიდებს მეხსიერების პრობლემებს და ინარჩუნებს ინფორმაციას. დარჩენილი კატეგორიული ცვლადები კოდირდება `OrdinalEncoder`-ით. სიხშირის რუქები ისწავლება მხოლოდ სატრენინგო მონაცემებიდან, რათა test სეტის ინფორმაცია არ "გაჟონოს" pipeline-ში.

### Nan მნიშვნელობების დამუშავება
რიცხვითი ცვლადების გამოტოვებული მნიშვნელობები შეივსო სატრენინგო სეტის **მედიანით** (`SimpleImputer(strategy='median')`). კატეგორიული ცვლადების გამოტოვებული მნიშვნელობები შეივსო **მოდით** (`SimpleImputer(strategy='most_frequent')`). ყველა ეს გამოთვლა ხდება sklearn Pipeline-ის შიგნით, რაც გარანტიას იძლევა, რომ test სეტზე გამოიყენება სატრენინგო სეტის სტატისტიკა.

### Cleaning მიდგომები
Cleaning-ის ძირითადი პრინციპი იყო: წავშალოთ სვეტები, რომლებიც ძალიან ბევრ ინფორმაციას კარგავს. კონკრეტულად, წაიშალა ყველა სვეტი, სადაც **50%-ზე მეტი მნიშვნელობა გამოტოვებული** იყო. ასევე წაიშალა `TransactionID`, რადგან ეს მხოლოდ შიდა იდენტიფიკატორია. სვეტების ამოშლა ხდებოდა train და test სეტებზე ერთნაირად, რათა მოდელი სხვადასხვა feature set-ზე არ გასულიყო.

## Feature Selection

### გამოყენებული მიდგომები და მათი შეფასება
Feature selection-ისთვის გამოვიყენეთ **Information Value (IV)** — მეტრიკა, რომელიც ზომავს თითოეული ცვლადის პრედიქტიულ ძალას target-თან მიმართებაში. IV გამოითვლება WoE (Weight of Evidence) ბინებზე და ინტერპრეტირდება შემდეგნაირად:

| IV მნიშვნელობა | ინტერპრეტაცია |
|---|---|
| < 0.02 | უსარგებლო |
| 0.02 – 0.1 | სუსტი |
| 0.1 – 0.3 | საშუალო |
| 0.3 – 0.5 | ძლიერი |
| > 0.5 | ძალიან ძლიერი |

ზღვარად ავირჩიეთ **IV > 0.02**, ანუ დარჩა ყველა ცვლადი, რომელსაც ჰქონდა თუნდაც სუსტი პრედიქტიული ძალა. IV გამოითვლებოდა 60,000-ელემენტიან შემთხვევით ნიმუშზე სისწრაფის გამო.

## Training

### ტესტირებული მოდელები
გავტესტეთ 5 სხვადასხვა მოდელი. თითოეულს ჰქონდა იგივე preprocessing pipeline — feature engineering, imputation და encoding. ვალიდაცია ხდებოდა 80/20 stratified split-ით, `random_state=42`.

| მოდელი | ჰიპერ-პარამეტრების კომბინაციები | საუკეთესო val AUC |
|---|---|---:|
| Logistic Regression | 4 (სხვადასხვა `C`) | ~0.83 |
| Random Forest | 4 (სიღრმე, ხეები, leaf ზომა) | ~0.92 |
| Gradient Boosting | 4 (სიღრმე, სწავლის სიჩქარე) | ~0.91 |
| AdaBoost | 4 (estimators, სწავლის სიჩქარე) | ~0.88 |

### Hyperparameter ოპტიმიზაციის მიდგომა
ყველა მოდელისთვის გამოვიყენეთ **manual grid search** — წინასწარ განსაზღვრული კომბინაციების სია, რომელიც loop-ში გაიარება. თითოეული კომბინაცია ილოგება ცალკე MLflow run-ად. Cross-validation-ის ნაცვლად გამოვიყენეთ ერთი 80/20 split, რადგან dataset-ი დიდია (~590,000 რიგი) და k-fold CV ძალიან ნელი აღმოჩნდა. XGBoost-ისთვის 15 კომბინაცია ვცადეთ, რადგან ის სხვა მოდელებთან შედარებით საუკეთესო შედეგს იძლეოდა და მეტი ექსპერიმენტირება გაზრდილი AUC-ის პოტენციალს ატარებდა.

### საბოლოო მოდელის შერჩევის დასაბუთება
საბოლოო მოდელად ავირჩიეთ **XGBoost** პარამეტრებით `n_estimators=200`, `max_depth=7`, `learning_rate=0.1`, `subsample=0.7`, `colsample_bytree=0.7`. ეს კომბინაცია გვაძლევს ბალანსს სიღრმესა (7) და სტოქასტიკურ რეგულარიზაციას (subsample და colsample_bytree) შორის. Logistic Regression-მა ვერ დაიჭირა არაწრფივი დამოკიდებულებები. Random Forest და Gradient Boosting კარგ შედეგებს იძლეოდა, მაგრამ XGBoost-ს ჩამორჩებოდა. AdaBoost ყველაზე სუსტი აღმოჩნდა. XGBoost-მა ყველა მოდელს შორის უმაღლესი `val AUC = 0.9537` აჩვენა, ამიტომ სწორედ ის შეირჩა Kaggle submission-ისთვის.

### ჩაწერილი მეტრიკების აღწერა
MLflow-ში ვლოგავდით ჰიპერ-პარამეტრებს და მეტრიკებს თითოეული run-ისთვის. ჩაწერილი პარამეტრები: მოდელის სპეციფიკური ჰიპერ-პარამეტრები (მაგ. `n_estimators`, `max_depth`, `learning_rate`) და `n_features` — IV-ის შემდეგ დარჩენილი feature-ების რაოდენობა. ჩაწერილი მეტრიკები: `train_auc`, `val_auc` და `overfit_gap` (სხვაობა train და val AUC-ს შორის). თითოეულ run-ს ასევე ენიჭება `fit_status` tag: `good_fit`, `overfit` (gap > 0.05) ან `underfit` (val_auc < 0.70). საუკეთესო მოდელი ხელახლა ტრენინგდება მთელ train სეტზე და ინახება MLflow Model Registry-ში `is_best=true` tag-ით.

### საუკეთესო მოდელის შედეგები
საუკეთესო მოდელი იყო **XGBoost** `n_estimators=200`, `max_depth=7`, `learning_rate=0.1`, `subsample=0.7`, `colsample_bytree=0.7` პარამეტრებით, რომელმაც validation სეტზე აჩვენა **AUC = 0.9537**. ეს მოდელი ხელახლა დავატრენინგეთ მთელ სატრენინგო სეტზე და შევინახეთ MLflow Model Registry-ში სახელით `XGBoost_FraudDetection`. `model_inference.ipynb` ატვირთავს ამ მოდელს რეესტრიდან და აგენერირებს `submission.csv`-ს Kaggle-ის test სეტისთვის.
